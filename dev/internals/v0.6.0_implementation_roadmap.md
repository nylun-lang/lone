## 1. Executive Implementation Strategy

The implementation is structured into **5 sequential phases** designed to minimize coupling and maximize testability at each layer of `pkg2`:

```
┌────────────────────────────────────────────────────────────────────────┐
│ Phase 1: Struct Initialization, Constructors & Field Modifiers         │
│   • Struct-Private Scope (_*), `ro` fields, `Type::(...)` constructors  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ Phase 2: Reference (`ref<T>`) & Pointer (`ptr<T>`) Semantics           │
│   • Non-null `ref`, nullable `ptr`, `p[i]` indexing, AddressTaken spill│
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ Phase 3: Grouped Syntax, Anonymous Functions & Tuples                  │
│   • `[...]` declarations, `fn(...) {}` literals, tuples & destructuring│
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ Phase 4: Interface Data Contracts (`Ifc*`)                             │
│   • `interface { ... }`, structural duck-typing, width subtyping       │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ Phase 5: Formatted String Interpolation (`f"..."`) & Display Traits    │
│   • `f"..."` scanning, `TrDisplay`, Stack-Buffered Single-Write codegen│
└────────────────────────────────────────────────────────────────────────┘
```

## 2. Phase Breakdown & Subsystem Tasks

### Phase 1: Struct Initialization, Constructors & Field Modifiers
- **Target RFC**: `RFC-20261104-struct_initialization_and_field_modifiers`
- **Subsystem Changes**:
  1. **`pkg2/lone-parser-ast`**:
     - Add `IsReadOnly bool` to `StructField`.
     - Add `SuffixConstructorCall{Args: []Expr}` to postfix suffixes.
  2. **`pkg2/lone-lexer`**:
     - `ro` token already exists (`TokenRo`).
  3. **`pkg2/lone-parser`**:
     - Parse `ro` prefix on struct fields in `parser.go`.
     - Parse `Type::(args...)` in Pratt parser (`pratt.go` `TokenColon2` case).
  4. **`pkg2/lone-analyzer`**:
     - Struct-Private Scope check: reject `s._field` access outside methods on `T` (`type/private-field-access`).
     - Raw aggregate restriction: reject `Type::{ ... }` outside associated methods if `T` has private fields (`type/raw-construct-private-fields`).
     - Enforce `__init__` constructor hook for `Type::(args...)` (`type/unresolved-constructor`).
     - Check `ro` immutability on field assignments (`type/immutable-field-write`).
     - Validate struct with `ro _*` field defines `__init__` (`type/missing-init-for-ro-private-field`).
  5. **`pkg2/lone-compiler-wir`**:
     - Lower `Type::(args...)` to call `Type.__init__(args...)`.
  6. **Tests**:
     - Unit tests in `pkg2/lone-parser/parser_test.go`, `pkg2/lone-analyzer/analyzer_test.go`, and end-to-end execution in `test2`.

---

### Phase 2: Reference (`ref<T>`) vs. Pointer (`ptr<T>`) Semantics
- **Target RFC**: `RFC-20261105-reference_and_pointer_semantics`
- **Subsystem Changes**:
  1. **`pkg2/lone-analyzer`**:
     - Evaluate `&x` on `let` as `ref<ro T>`, `&raw x` on `let` as `ptr<ro T>`.
     - Validate indexing `p[i]` permitted on `ptr<T>`, rejected on `ref<T>`.
     - Reject mutation on `ref<ro T>` (`type/immutable-reference-write`) and `ptr<ro T>` (`type/immutable-pointer-write`).
     - Mark `sym.AddressTaken = true` when address-of operator is applied to local bindings.
  2. **`pkg2/lone-compiler-wir`**:
     - Datastack frame allocation: variables with `AddressTaken == true` allocate frame slots in the Page 0 datastack.
     - Lower `&x` and `&raw x` to `sp + slotOffset`.
     - Lower pointer indexing `p[i]` to `p + i * sizeof(T)`.
  3. **Tests**:
     - Analyzer diagnostics and Wasm execution tests in `pkg2/lone-compiler-wir/wir_test.go`.

---

### Phase 3: Grouped Declarations, Anonymous Functions & Tuples
- **Target RFC**: `RFC-20261105-grouped_declarations_anonymous_functions_and_tuples`
- **Subsystem Changes**:
  1. **`pkg2/lone-parser-ast`**:
     - Add `AnonFnExpr` with `Params`, `ReturnType`, `Body`.
     - Add `TupleType` and `TupleExpr`.
  2. **`pkg2/lone-parser`**:
     - Grouped bracket syntax `[id1, id2, ...]: Type [= default]` in parameters, struct fields, and `let`/`var` bindings.
     - Parse `fn(...) [RetType] { ... }` in Pratt prefix position.
     - Parse `(T1, T2, ...)` tuple types and `(e1, e2, ...)` tuple expressions.
     - Parse `let (a, b) = pair` destructuring pattern.
  3. **`pkg2/lone-analyzer`**:
     - Grouped declarations: unroll every identifier with `Type`.
     - Tuple type checking, pattern arity checking (`type/tuple-arity-mismatch`), positional indexing `t.0`, `t.1`.
     - Enforce closure capture rule: reject escaping closures capturing stack references (`closure/escaping-reference-capture`).
  4. **`pkg2/lone-compiler-wir`**:
     - Lower tuples to Datastack SRET.
     - Lift anonymous functions to package-level symbols with closure payloads.

---

### Phase 4: Interface Data Contracts (`Ifc*`)
- **Target RFC**: `RFC-20261104-interface_data_contracts`
- **Subsystem Changes**:
  1. **`pkg2/lone-lexer`**:
     - Add keyword `interface` -> `TokenInterface`.
  2. **`pkg2/lone-parser-ast`**:
     - Add `TYPE_DEC_INTERFACE` kind and `InterfaceField`.
  3. **`pkg2/lone-parser`**:
     - Parse `type IfcName = interface { [ro] name: Type, ... }`.
  4. **`pkg2/lone-analyzer`**:
     - Enforce `Ifc` prefix naming convention (`naming/interface`).
     - Implement structural satisfaction engine: `TypeSatisfiesInterface(target, ifc)`.
     - Support width subtyping and covariant read-only field compatibility.
     - Evaluate generic constraints `where { T satisfies IfcName }`.
  5. **`pkg2/lone-compiler-wir`**:
     - Zero-cost monomorphization of interface-constrained generic functions.

---

### Phase 5: Formatted String Interpolation & Display Traits
- **Target RFC**: `RFC-20261105-string_interpolation_and_display_traits`
- **Subsystem Changes**:
  1. **`pkg2/lone-lexer`**:
     - Recognize `f"` format string literal prefix.
  2. **`pkg2/lone-parser-ast`**:
     - Add `InterpolatedStringExpr{Parts: []Expr}`.
  3. **`pkg2/lone-parser`**:
     - Parse interleaved string literals and `${expr}` blocks.
  4. **`pkg2/lone-analyzer`**:
     - Validate interpolated expressions implement `TrDisplay` or are primitives (`type/missing-trait-impl`).
  5. **`pkg2/lone-compiler-wir`**:
     - Output statement position (`println(f"...")`): format into Page 0 datastack buffer and emit exactly 1 atomic `fd_write` syscall.
     - Value position (`let s = f"..."`): allocate contiguous string on Managed Store (`#alloc`).

## 3. Verification Criteria & Test Milestones

- Every phase must pass 100% of existing tests: `go test ./...`.
- Each phase introduces targeted unit tests in `pkg2` and behavioral test programs in `test2`.
- Documentation (`dev/SPEC.md` and session logs) updated upon completion of each phase.
